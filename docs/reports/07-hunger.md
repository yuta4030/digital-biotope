# 07 空腹度

[03](03-vision-and-pursuit.md) で「追跡には速度差と捕獲成功率の**両方**が要る」と結論した。
その前提を1つ外したら、速度差なしで追跡が成立した記録。

- 実行: `node docs/reports/scripts/07-hunger.ts`（4 worker で3分6秒 / CPU時間 12分0秒）
- 条件: 8000ステップ、後半4000ステップで統計、5〜8シード

## なぜ速度差が要ったのか

03で速度差が必須だった理由は、追跡そのものではなく**逃走の優先順位**にあった。

```
捕食者から逃げる → 獲物を追う → 草の多い方へ → ランダム
```

逃走が最優先なので、捕食者が視界にいる限り草食動物は餌を探さない。
等速だと逃げ切られて**遭遇が一度も起きず**、捕食者は必ず餓死する。
捕獲成功率をいくら上げても、狩る機会そのものが無いので効かない。

改めて5シードで測っても、成功率1.0でも捕食者は全滅する。

| 速度差なし・空腹なし | 生存 | 草食 | 肉食 |
|---|---|---|---|
| 成功率 0.04 | 0/5 | 1074 | **0** |
| 成功率 0.20 | 0/5 | 1074 | **0** |
| 成功率 0.50 | 0/5 | 1073 | **0** |
| 成功率 1.00 | 0/5 | 1073 | **0** |

草食が1073で頭打ちなのは草の生産量で決まる上限（`0.06 × 10800 ÷ 0.6 ≈ 1080`）で、
捕食圧が実質ゼロであることを示している。

## 入れたもの

種定義に `hungerThreshold` を足し、エネルギーがこれを下回ったら優先順位を入れ替える。

```
満腹: 捕食者から逃げる → 獲物を追う → 草の多い方へ → ランダム
空腹: 獲物を追う → 草の多い方へ → 捕食者から逃げる → ランダム
```

空腹側でも逃走を最後に残してある。餌が見えないなら逃げた方が得なので、
「腹が減ったらリスクを取る」であって自暴自棄になるわけではない。

既定は0で、その場合 `energy < 0` は生存個体では成立しないため分岐に入らない。
乱数の消費列も変わらないので、**既存6構成の結果は数値まで一致する**（[02](02-preset-validation.md) の表で回帰確認済み）。

## 結果: 空腹閾値だけで共存する

速度は両方1（差なし）、捕獲成功率0.1で固定し、草食の空腹閾値だけを振る。
繁殖閾値が20なので、閾値8は「繁殖には遠いが死んではいない」あたり。

| 空腹閾値 | 生存 | 草食（平均と振れ幅） | 肉食 |
|---|---|---|---|
| 0 | 0/5 | 1073 (880-1300) | **0** |
| 2 | 0/5 | 1073 (914-1305) | **0** |
| 3 | 5/5 | 935 (662-1268) | 180 (50-273) |
| 4 | 5/5 | 896 (667-1164) | 227 (146-320) |
| 6 | 5/5 | 848 (529-1196) | 278 (190-398) |
| **8** | **5/5** | **821 (496-1168)** | **308 (215-416)** |
| 10 | 5/5 | 777 (429-1331) | 351 (179-458) |
| 12 | 5/5 | 730 (269-1437) | 392 (219-566) |
| 15 | 5/5 | 712 (106-**2162**) | 389 (107-673) |
| 20 | 5/5 | 728 (**23**-**2576**) | 327 (19-701) |

- **閾値2と3の間に境界がある。** 2以下では空腹になる個体がほとんど出ず、遭遇が起きない
- 閾値を上げるほど草食が減り肉食が増える。**空腹閾値は遭遇率のつまみとして効く**
- 平均だけ見ると15や20も問題なく見えるが、**振れ幅が急に広がる**。
  閾値20では草食が23まで落ちる回があり、あと一歩で全滅する

既定は8。振れ幅がまだ落ち着いていて、草食と肉食の比が他の構成と揃う位置に置いた。
8シードでも 818(496-1258) / 310(215-416) で 8/8。

## 空腹閾値と捕獲成功率は対称ではない

閾値は「どれくらいの頻度で捕まえられる状態になるか」、成功率は「捕まえられる状態で
実際に仕留められるか」を決める。どちらも捕食圧を上げるので、当初は
**積で決まる**と考えていた。下側だけを見ると実際そう見える。

| | 成功率 0.05 | 0.1 | 0.2 | 0.4 |
|---|---|---|---|---|
| **閾値 4** | **0/5** 肉食0 | 5/5 896 / 227 | 5/5 793 / 262 | 1/5 879 / 129 |
| **閾値 8** | 5/5 1041 / 55 | 5/5 821 / 308 | 5/5 773 / 284 | **0/5** 38 / 15 |
| **閾値 12** | 5/5 957 / 183 | 5/5 730 / 392 | 5/5 728 / 317 | **0/5** 0 / 0 |

- **下側（餓死）は積で決まる。** 閾値4×成功率0.05 では捕食者が餓死するが、
  どちらか一方を上げれば超えられる（閾値8×0.05 も 閾値4×0.1 も共存する）
- **上側（共倒れ）は成功率だけで決まる。** 成功率0.4はどの閾値でも壊れるのに、
  閾値は20まで上げても壊れない

非対称なのは、2つが同じものを上げていないため。
**閾値を上げると草食は逃げない時間が増えるが、そのぶん採餌して繁殖もする。**
損だけでなく得も増えるので、増えた死亡を自分で埋め合わせられる。
成功率を上げるのは遭遇を死に変換する率を上げるだけで、埋め合わせが無い。

閾値20で振れ幅だけが広がって平均が落ちないのは、この埋め合わせが効いている姿だと考えている。

## 対照: 速度差がある構成では効果が小さい

既定の追跡構成（速度2・成功率0.04）に空腹を足しても、系はほとんど動かない。

| 空腹閾値 | 生存 | 草食 | 肉食 |
|---|---|---|---|
| 0 | 5/5 | 794 | 243 |
| 4 | 5/5 | 792 | 270 |
| 8 | 5/5 | 777 | 293 |
| 12 | 5/5 | 762 | 321 |

肉食が3割増えるが、草食はほぼ変わらず全条件で 5/5。
速度差がある時点で遭遇はすでに足りていて、**空腹が効くのは遭遇が枯れている系だけ**。

なお実装前は「速度差と空腹の両方があると過捕食で崩れる」と予想していたが、外れた。
崩す力があるのは成功率の方で、遭遇率をどこから供給するかは系の安定性をあまり変えない。

## 03の結論の訂正

03の「速度差と捕獲成功率の**両方**が要る」は、`hungerThreshold = 0` の下では正しい。
より正確には次のようになる。

> 追跡が成立するには、**遭遇が起きること**と**遭遇が確実に死につながらないこと**が要る。
> 速度差は遭遇を作る手段の1つにすぎず、空腹で逃走をやめさせても遭遇は作れる。

捕獲成功率 < 1 の方は、どちらの経路でも必要なまま変わらない。
