## 再現方法

各レポートの数字は [scripts/](scripts/) のスクリプトが出力したもの。

```bash
node docs/reports/scripts/01-coexistence-region.ts
```

Node 24 は `.ts` をそのまま実行できるのでビルドは要らない。所要時間はスクリプト
冒頭のコメントに書いてある。視野を使う実験は遅く、03と05はそれぞれ10分前後かかる。

## 測り方

全レポート共通の方針。

- **同じ条件をシードだけ変えて複数回走らせる。** 1回では、まぐれで生き残った条件と
  安定な条件が区別できない。表の `OK 5/5` はそのうち何回で全種が生き残ったかを表す
- **統計は後半半分だけで取る。** 前半は初期配置から落ち着くまでの過渡状態で、
  共存できるかの判断には邪魔になる
- **平均だけでなく最小・最大も見る。** 平均が同じでも、振れ幅が広い条件は
  谷が0に当たった時点で絶滅する。安定性は振れ幅に出る
- **形質を測るときは、平均を取る前に経過を並べる。** 個体数は数百ステップで
  落ち着くが、遺伝する形質は世代を通してしか動かない。後半半分がまるごと
  過渡状態のことがあり、そうなると後半だけで統計を取る約束が効かなくなる
  （[07](07-speed-evolution.md)）
- **有無で差が出た軸は、強さも振る。** 「Xがあると結果が変わる」まではすぐ言えるが、
  Xを強めて結果が追随しなければ、Xが原因だという話は成り立たない。
  強さが測れない量なら、測れる量に直してから振る（[07](07-speed-evolution.md)）

シードを固定すれば結果は完全に再現する。乱数は `Math.random()` ではなく
シード付きの実装（[rng.ts](../../src/core/rng.ts)）を通している。

## この記録が示していること

6構成のうち**4つは最初に書いたとき壊れていた**。しかも4つとも、コードとしては
正しく動いていて、型検査も通り、画面上でも動いているように見えた。

- 「雑食」は草食動物が250ステップで絶滅していた
- 「4層」は頂点捕食者が中位捕食者より多い逆ピラミッドだった
- 「視野」は3回作り直した
- 「燃費」は最初の設計だと警戒型が捕食者に対して無敵になっていた

いずれも**数字を見て初めて分かった**。眺めているだけでは気づけない類の壊れ方をする。

読み違えも4回している。すべて記録として残してある。

- [04](04-metabolism-stability.md) — 3シードで非単調な機構を「発見」しかけた。8シードで消えた
- [06](06-enrichment.md) — 条件の違う2つの結果を比べて、誤った因果を報告した
- [07](07-speed-evolution.md) — 過渡状態の後半平均を収束先として読みかけた。2回

原因は毎回違う。シード数が足りない、軸を固定していない、時間が足りない。
共通しているのは、**確かめる手間より説明を思いつく速さが勝っていた**こと。
