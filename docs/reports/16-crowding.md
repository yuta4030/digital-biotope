# 16 頻度依存 — 増えた側を叩くと共存が生まれる

[15](15-frequency-dependence.md) で「均等に減らすだけでは共存しない」ことを潰した。
その対偶側で、**増えた側ほど叩く**と共存が生まれるのかを測った記録。

**生まれた。** 自種の密度に比例した死亡を入れると、rate 0.1 以上で草食Bが
8シードすべてで生き残る（rate 0.2 で A 665 / B 287）。対照は**全 rate で 0/8**。

対照が効いているのが要点。`scope: 'all'`（全種の合計密度を数える）は関数形も
つまみも同一で、**誰の密度を数えるかだけ**が違う。しかも同じ rate では all のほうが
**多く**取り除く（rate 0.2 で 13.86 対 9.70）。**多く殺しているのに共存しない。**
効いているのは死の量ではなく、死の向きだと言い切れる。

ただしこの軸は**答えを直接書いている**。自種密度に比例した死亡は共存条件
（種内の抑制 > 種間の抑制）を式で置いたものなので、共存するのは半ば当たり前。
ここで測ったのは機構の面白さではなく、**接触感染（段2）が狙うべき的**のほう。

- 実行: `node docs/reports/scripts/16-crowding.ts`（4スレッドで4分11秒）
- 条件: 8000ステップ / 後半4000ステップで統計 / 8シード。
  節5だけ30000ステップ（[02](02-preset-validation.md)・[14](14-mass-death.md)と同じ枠）

## 何を確かめたかったか

[DIRECTION](../DIRECTION.md) の次の一手は kill-the-winner だが、本命の実装は
**接触で伝わる感染**で、そちらは個体ごとの感染状態を持つ必要がある。
作ってから効かなかったとき、**機構が効かないのか実装を間違えたのか**を
区別できない。

そこで頻度依存を手で書いた版を先に置いて、効くかどうかだけ確かめる。
これが段1。段2で感染を実装したときの、答え合わせの基準になる。

## 設計: 何を固定するか

```
1ステップの追加死亡確率 = rate × (数える対象の個体数 ÷ セル数)
```

- `scope: 'self'` — **自種だけ**を数える。A（1298）は B（300）の4倍の密度なので、
  同じ rate でも A のほうが強く叩かれる。これが kill-the-winner の中身
- `scope: 'all'` — 全種の合計を数える。**対照**

対照をこの形にしたのは、[15](15-frequency-dependence.md) の大量死と比べるより
厳密だから。15 の比較は「密度に比例する死」対「比例しない死」で、関数形が違う。
ここは関数形もつまみも同じで、**参照する個体数が自種か全種か**しか違わない。

密度は**世界全体の平均**（個体数 ÷ セル数）で、局所密度ではない。空間の粗密が
混ざると、効いたときに「頻度依存が効いた」のか「空間構造が効いた」のかを
分けられなくなる。空間を持ち込むのは段2の仕事。

### 走査順の罠を先に潰す

個体数は**そのステップの死亡処理を始める前の値**で固定してある。殺しながら
数え直すと、走査順の早い個体ほど高い密度で抽選されることになる。
[03](03-vision-and-pursuit.md) で3回踏んだ「走査順のバイアスが生態学的な現象に
見える」が、そのまま再現するところだった。

## 節1 回帰

`crowding` を書かない構成は乱数を1つも消費しない。[15](15-frequency-dependence.md)
の節1と数字が1つも違わないことを確認した。

| | 生存 | 草食A | 草食B | 肉食 |
|---|---|---|---|---|
| 肉食あり（既定） | OK 8/8 | 574 (210-1064) | 505 (123-896) | 121 (8-346) |
| 肉食なし | -- 0/8 | 1298 (1231-1374) | **0** | — |

肉食なしでのBの絶滅は 8/8、中央 643 歩（479-756）。15 と完全に一致。

## 節2 self — 閾値は 0.05 と 0.1 の間

| rate | 生存 | 草食A | 草食B | Bの絶滅（中央） | 除去/歩 計 (A / B) |
|---|---|---|---|---|---|
| 0.02 | -- 0/8 | 1234 (1168-1308) | **0** | 799 (664-908) | 2.81 (2.81 / 0.00) |
| 0.05 | -- 0/8 | 1147 (1073-1214) | **0** | **1594** (919-2300) | 6.09 (6.09 / 0.00) |
| **0.1** | **OK 8/8** | 967 (886-1064) | **76** (27-132) | 絶滅なし | 8.72 (8.66 / 0.06) |
| **0.2** | **OK 8/8** | 665 (587-753) | **287** (226-358) | 絶滅なし | 9.70 (8.17 / 1.53) |
| **0.5** | **OK 8/8** | 444 (386-514) | **318** (256-378) | 絶滅なし | 13.84 (9.11 / 4.72) |
| **1.0** | **OK 8/8** | 322 (263-389) | **264** (207-322) | 絶滅なし | 16.10 (9.61 / 6.49) |

閾値がはっきり出ている。そして**閾値の下側では絶滅が遅れる**：rate 0.05 で
中央 643 → **1594 歩**。効いてはいるが足りない、という形が見えている。
効き方が階段ではなく、下から効きが積み上がって 0.1 で止まる。

上げるほど A と B の比が均等に寄る（967:76 → 322:264）。用量反応が単調なので、
バグで共存しているという読みは取りにくい。

## 節3 all — 多く殺しても共存しない

| rate | 生存 | 草食A | 草食B | Bの絶滅（中央） | 除去/歩 計 |
|---|---|---|---|---|---|
| 0.02 | -- 0/8 | 1234 (1169-1298) | **0** | 630 (573-791) | 2.81 |
| 0.05 | -- 0/8 | 1147 (1071-1212) | **0** | 698 (583-1009) | 6.08 |
| 0.1 | -- 0/8 | 1029 (953-1117) | **0** | 810 (756-1417) | 9.79 |
| 0.2 | -- 0/8 | 865 (763-958) | **0** | 963 (708-1376) | 13.86 |
| 0.5 | -- 0/8 | 613 (536-704) | **0** | 1051 (843-1248) | 17.46 |
| 1.0 | -- 0/8 | 426 (352-493) | **0** | 1099 (821-1552) | 16.90 |

**全滅。** A の平均は 1234 から 426 まで下がっているので、操作自体は確かに効いている。
効いた結果として起きたのは「Aが減る」だけで、Bは1シードも助からない。

絶滅の時刻は 630 → 1099 と後ろへ動く。15 の大量死で見たのと同じ形で、
**均等に減らす操作は排除を遅くするだけ**という結論が、まったく別の関数形で
引き直されたことになる。

rate 0.5 → 1.0 で除去量が 17.46 → 16.90 と**下がる**のは、Aの個体数が
先に落ちるため。密度に比例する死は、強くするほど自分の餌を減らす。

## 節4 除去量の突き合わせ

self が共存して all が共存しないとき、それを「頻度依存だから」と言えるのは
**all のほうが多く取り除いている**場合に限る。少なく取り除いて失敗しているなら、
ただの強さ不足かもしれない。

| rate | self | all | all/self |
|---|---|---|---|
| 0.02 | 2.81 | 2.81 | 1.00 |
| 0.05 | 6.09 | 6.08 | 1.00 |
| **0.1** | 8.72 | 9.79 | **1.12** |
| **0.2** | 9.70 | 13.86 | **1.43** |
| **0.5** | 13.84 | 17.46 | **1.26** |
| **1.0** | 16.10 | 16.90 | **1.05** |

**共存が起きる rate では、常に all のほうが多く取り除いている。**
強さ不足では説明できない。

rate 0.02・0.05 で比が 1.00 なのは、その条件では B が絶滅していて
自種密度＝合計密度になるため。対照として意味を持つのは 0.1 以上の行だけ。

| crowding なし | 0/8 | 0/8 | 1298 | 0 |

## 段2 が狙うべき強さ

段1の一番の収穫はこれ。**共存する条件で、多いほうから毎ステップ何%を
取り除いているか**が数字で出た。

| rate | Aから除去 | Aの平均 | 割合/歩 | Bから除去 | Bの平均 | 割合/歩 |
|---|---|---|---|---|---|---|
| 0.1（閾値） | 8.66 | 967 | **0.90%** | 0.06 | 76 | 0.08% |
| 0.2 | 8.17 | 665 | **1.23%** | 1.53 | 287 | 0.53% |

接触感染で共存を作るなら、**多いほうに 1%/歩 前後**の死亡を与え、
少ないほうにはその半分以下に留める必要がある。

同セルの接触率は密度 0.12個体/セルから見積もると1個体あたり 0.1回/歩 程度なので、
接触1回あたり数%の伝染確率があれば桁は届く。**ただしこれは見積もりで、測っていない。**

## 外した見立て

**「開始時に両種とも300体なので、self でも密度に差がつかず、効き始めが
排除に間に合わない」** — 半分外れた。

rate 0.1 以上では間に合っている。ただし完全な外れではなく、**閾値の下側で
予想した形がそのまま見えた**。rate 0.05 は絶滅を 643 → 1594 歩へ遅らせるが
止められない。効き始めが遅いという読み自体は正しくて、それを押し切るだけの
強さが 0.1 以上にはあった、というだけだった。

## 測っていないこと

- **これは機構ではない。** 自種密度に比例した死亡は共存条件を式で書いたもので、
  「そう書けばそうなる」以上のことは言っていない。接触感染で同じことが
  **接触の数え方から自然に出るか**が本題で、それは段2
- **捕食者がいる場合。** 全部の条件で肉食を外している。既存の競合構成に
  crowding を足すと、キーストーン捕食と頻度依存が両方効く状態になる。
  そこで何が起きるかは測っていない
- **rate 0.1 の B は谷で27体まで落ちる。** 30000歩では 8/8 だが、
  [14](14-mass-death.md) の「崩壊確率は走行が長いほど積み上がる」がここにも効くはず。
  侵入の実験（15万歩級）で使うなら 0.2 以上にすべきだが、その境目は測っていない
- **A と B の非対称性がどこから来るか。** 共存点でも A 665 / B 287 と偏っている。
  代謝（0.5 対 0.62）と繁殖確率（0.09 対 0.075）の差がそのまま出ているはずだが、
  どちらがどれだけ効いているかは分けていない
- **速度の分岐（[10](10-speed-evolution.md) の目型・足型）には効かない。**
  同一種内の形質の分布なので、種を単位にした密度では区別できない。
  そちらをやるには形質空間での密度が要る
