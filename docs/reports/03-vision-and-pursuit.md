# 03 視野と追跡

動物に目を持たせて、獲物を追い・捕食者から逃げるようにした記録。
**素直に実装したものは3回とも壊れていた。**

- 実行: `node docs/reports/scripts/03-vision-and-pursuit.ts`（4 worker で1分52秒）
- 条件: 8000ステップ、後半4000ステップで統計、5シード（一部6シード）

## それまでの捕食

視野を入れる前は、動物はランダムウォークしていた。捕食は
「移動した結果たまたま同じセルにいたら成立」という判定で、
**移動速度を上げても遭遇率がほとんど変わらない**という欠点があった。

そこで視野を追加し、視野が1以上なら
「捕食者から逃げる → 獲物を追う → 草の多い方へ → ランダム」の優先順で動くようにした。

## 壊れ方1: 獲物のいた場所を狙っていた

最初の実装は、視界用の空間インデックスを**移動前**に作っていた。
そのため捕食者は獲物の旧位置に向かい、獲物も同時に動くのでそこは空になっている。

結果、**視野を広げるほど捕食者が減った**。

| 草食の視野 | 肉食の視野 | 草食 | 肉食 |
|---|---|---|---|
| 0 | 0 | 687 | 397 |
| 0 | 1 | 636 | 318 |
| 0 | 2 | 637 | 297 |
| 0 | 4 | 1057 | **39** |

ランダムウォークより当たらない。捕食者が確率質量を「獲物が去った1マス」に
集中させてしまい、他の獲物と出会う機会も捨てていた。

**直し方**: 種インデックス順（下位の獲物 → 上位の捕食者）に動かし、
視野を使う種の手番の前に空間インデックスを作り直す。
これで捕食者は獲物の移動後の位置を見て追える。

## 壊れ方2: 同点の走査順バイアスで群れが一方向に流れた

次に、草食動物が視野を持つと個体数が **1080 → 150** に激減した。

原因は草の探索。「視界内で最も草が多いセル」を選ぶ実装で、
同点のときに走査順の最初（真上）を取っていた。
未採食のセルは軒並み上限値8で**同点だらけ**なので、
群れ全体が上へ流れる人工的な波になり、採食効率が壊滅していた。

**直し方**: 同距離・同量の候補から等確率で選ぶ（リザーバサンプリング）。
これで草食は理論上限どおりの1074に戻った。

このバグは「実装の都合が生態系の挙動として観察されてしまう」典型で、
数字を見なければ「視野を持つと群れて非効率になるのだな」と誤って納得していたと思う。

## 壊れ方3: 追跡が決定的すぎて共存域が無かった

移動順を直すと、今度は捕食者が強くなりすぎた。

| 草食の視野 | 肉食の速度 | 結果 |
|---|---|---|
| 2 | 1 | 0/5 — 肉食が絶滅（草食は1073で無傷） |
| 2 | 2 | 0/5 — **両方絶滅** |
| 2 | 3 | 0/5 — **両方絶滅** |

理由は追跡に確率が無いこと。獲物が先に動いて逃げ、捕食者が追う。

- **等速なら**正味の距離が縮まらず、捕食者は永遠に追いつけない → 遭遇ゼロ
- **速い方が勝つなら**必ず追いつく → 100%捕食 → 獲物を絶滅させる

二択で、中間が無い。

**直し方**: 捕獲成功率を追加した。同じセルの獲物に襲いかかっても、
成功するのは確率で決まる（狩りは1ステップに1回、失敗するとその回は何も食べられない）。
実際の狩りはほとんど失敗するので、モデルとしても自然になる。

## 追跡の成立条件

捕獲成功率を入れると共存域が現れる。草食は視野2で逃げ、肉食は速度2・視野3・利得18。

| 捕獲成功率 | 生存 | 草食 | 肉食 |
|---|---|---|---|
| 0.50 | 0/5 | 0 | 0 |
| 0.25 | 0/5 | 0 | 0 |
| 0.12 | 0/5 | 0 | 0 |
| 0.08 | 0/5 | 0 | 0 |
| **0.05** | **5/5** | **727** | **236** |
| 0.03 | 0/5 | 1073 | 0 |

窓が狭い。0.08で共倒れ、0.03で捕食者が餓死する。

**速度差も必須**で、こちらは成功率では代替できない。

| 肉食の速度 | 捕獲成功率 | 結果 |
|---|---|---|
| 1 | 0.50 | 0/5 — 肉食が絶滅 |
| 1 | 0.12 | 0/5 — 肉食が絶滅 |
| 1 | 0.03 | 0/5 — 肉食が絶滅 |

等速だと**遭遇そのものが起きない**ので、成功率をどれだけ上げても効く場面が無い。
捕獲成功率は「出会ったあと」の話で、出会えないことの解決にはならない。

> **後日訂正**: 必須なのは速度差ではなく**遭遇**だった。
> 逃走が最優先で「捕食者が見えている限り餌を探さない」という当時の実装では、
> 等速にすると遭遇がゼロになる。空腹時に採餌を優先させると、等速のままでも
> 遭遇が生まれて共存する（[07](07-hunger.md)）。この節の表は
> `hungerThreshold = 0` の下では今も再現する。

## 採用値

6シードで詰めた結果。

| 成功率 | 利得 | 生存 | 草食 | 肉食 |
|---|---|---|---|---|
| 0.03 | 18 | 0/6 | 1073 | 0 |
| **0.04** | **18** | **6/6** | **794 (408-1470)** | **243 (138-325)** |
| 0.05 | 18 | 6/6 | 726 (32-2734) | 235 (27-461) |
| 0.06 | 18 | 4/6 | 458 (0-2622) | 143 (0-509) |
| 0.03 | 30 | 6/6 | 721 (41-2651) | 396 (67-763) |

0.04 と 0.05 はどちらも6/6だが、**振れ幅で選んだ**。
0.05は草食の谷が32まで落ちる（絶滅寸前）のに対し、0.04は408で余裕がある。
平均だけ見ていると同等に見える。

## 計算コスト

視野は1個体あたり (2r+1)² セルを走査するので明確に遅い。草食約1000個体で測定。

| 視野 | steps/sec |
|---|---|
| 0 | 7,841 |
| 1 | 3,939 |
| 2 | 2,480 |
| 3 | 1,480 |
| 5 | 733 |
| 8 | 318 |

視野0の約25倍（視野8）まで開く。視野を使う種の手番前に空間インデックスを
作り直すぶんの費用も含まれている。

## 分かったこと

**「もっともらしい実装」が3回続けて間違っていた。** しかも3回とも、
バグとして落ちるのではなく生態系の挙動として現れた。

- 1回目は「視野があると捕食者が不利になる」ように見えた
- 2回目は「視野があると草食が群れて非効率になる」ように見えた
- 3回目は「速度差があると捕食者が強すぎる」ように見えた

どれも生態学的にありえそうな話で、数字と突き合わせなければ
そのまま結論にしていたと思う。1と2は実装の誤りで、3だけがモデルの不足だった。
